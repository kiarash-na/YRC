## Class merging (`cn`)

Always `import { cn } from "@/lib/utils"` — never from the `cn` package directly (eslint `no-restricted-imports` enforces it). The project `cn` registers the custom type scale (`text-hero`, `text-display`, `text-h1`…`text-caption`) as font-size; the stock merger treats them as colors and silently drops the size when a `text-<color>` follows. `shadcn add` writes `from "cn"` — rewrite the import after adding a component. New `--text-*` tokens in `globals.css` must be added to `src/lib/utils.ts` too.

## Images (ImageKit)

- Always use `Image`/`Video` from `@/components/imagekit` for ImageKit-hosted assets (drop-in replacements for `next/image` / `<video>`). Never raw `<img>`/`<video>`.
- `urlEndpoint` comes from the provider in the root layout; never pass it per-component unless overriding.
- Keep `responsive` at its default `true` so srcset is auto-generated. Always set explicit `width`/`height` (or `fill`) to prevent CLS.
- Lazy loading is the default; use `loading="eager"` or `priority` only for above-the-fold/LCP images.
- For hero/LCP images use the official LQIP pattern: `buildSrc` with `transformation: [{ quality: 10, blur: 90 }]` as a background-image placeholder, cleared in `onLoad`.
- Never hardcode output format (`f-*`) or quality: automatic format conversion (AVIF/WebP via Accept header) and default quality 80 are already optimal per ImageKit docs. Use `transformation` only for sizing/cropping.
- No query strings in `src`; use the `queryParameters` prop. `src` is a relative path against the urlEndpoint.
- Videos: `preload="none"` + an `ik-thumbnail.jpg` poster via `buildSrc`.

## Motion & video

All motion is slow, subtle and gated on `prefers-reduced-motion` (see the "Motion" notes in `globals.css`). Use the existing primitives instead of new libraries:
- `.yrc-hero-in` (CSS load-in, stagger with inline `animationDelay`) for above-the-fold page heroes; `<Reveal>` (`@/components/reveal`) for everything below the fold — sections are wrapped at page level. `<Reveal className="yrc-stagger …">` makes its direct children arrive one by one (card grids).
- `.yrc-drift` (slow breathing zoom) on large hero images, `.yrc-lift` on cards, `.yrc-live-dot` for "next/live" accents, `.yrc-tick` on success check icons, `<CountUp>` for scoreboard numbers, `.yrc-read-progress` on articles.
- Covers morph between card and detail page via React `<ViewTransition name="event-cover-<slug>" | "post-cover-<slug>" share="yrc-morph" default="none">`. A name must appear once per page (that's why `PostCard` only morphs with the `morph` prop).
- Decorative/ambient clips use `<AmbientVideo>` (`@/components/ambient-video`): muted loop, plays only while on screen, never autoplays for reduced motion / Save-Data / 2G, image poster underneath, pause toggle (`controls` for content clips). The hero uses the same `useAmbientPlayback` hook. Videos are served with `ORIGINAL_VIDEO` (`tr=orig-true`) and posters are real images — the ImageKit video-transformation quota is exhausted, so `ik-thumbnail.jpg` fails. Known clips: `/YRC/Home/hf_20261122_111745_bc09fc36-b5d4-4bb9-bd12-f5d1a2d06393.mp4` (hero background, the crew at golden hour, 1168×768, 5.4 s, ~7 MB), `/YRC/19538560-uhd_3840_2160_24fps.mp4` (old hero clip, 4K landscape, ~47 MB, unused), `/YRC/Community/IMG_2483.MP4` and `IMG_2484.MP4` (portrait balance-board drills, 576×1024 — use in 3:4 / 4:5 slots).

## Members, scoring & auth (Supabase + Strava)

- **Route groups**: `(marketing)` = public site (Navbar/Footer/Tally live in its layout); `(auth)` = login, `/profile`, `/checkin/[token]`; `(admin)` = `/admin/*`. Root layout keeps only html/body/font/ImageKit.
- **Auth**: Strava OAuth (scope `read`) is the primary login — `/auth/strava` → `/auth/callback/strava` → `/auth/confirm`. With `?mode=link` the same flow links a Strava athlete to the already signed-in account (from `/profile/settings`) instead of minting a new one; a clash with another member is refused (`error=strava_taken`). Email magic-link login (`signInWithOtp`, PKCE) is the secondary method; both paths land on `/auth/confirm` (handles `code` exchange and `token_hash` verify). Strava never returns an email, so Strava auth users get a synthetic `strava-<athlete_id>@strava.yasrise.run` email. Every new auth user gets a blank `profiles` row via the `on_auth_user_created` trigger. Session refresh + route gating happen in `src/proxy.ts` (Next 16 renamed middleware → proxy). Transactional email is branded React Email rendered by the `send-auth-email` edge function via the Supabase "Send Email" auth hook + Resend API — the hook is LIVE (see `supabase/README.md`); the Resend SMTP config remains in Supabase Auth only as a fallback. When editing the function: the bundler requires the classic JSX transform (`"jsx": "react"` in deno.json — `react-jsx` causes BOOT_ERROR) and every response must be JSON (the hook rejects other content-types).
- **Database**: Supabase, 13 tables (see `supabase/README.md`; migrations 0001–0008 were applied by hand in the SQL editor, so the remote history starts at 0009 — that's expected). Events, journal posts (`posts`) and page copy (`content_blocks`) all live in the DB; the old MDX/data files are retired. Event **registration** (`event_registrations`, 0009) is the member's own RLS-guarded insert via `registerForEvent()` — the event page's Register CTA sends guests to `/login?next=/events/<slug>?register=1` and registers them on return. Members can **unregister** from an upcoming event (confirm dialog) via `unregisterFromEvent()` — members have no DELETE grant, so it deletes with the service role after identifying the member from their own session, own row + not-past event only. **GPX routes** (0010): admins upload a .gpx in the event form → `routeFields()` parses/simplifies it (`src/lib/gpx.ts`) into `events.route_line` (jsonb [lng,lat][]) and stores the file in the public `event-routes` Storage bucket (`route_gpx_path`); the event page renders it with the vendored mapcn map (`src/components/ui/map.tsx`, MapLibre + free CARTO tiles). Weekly copies carry the route. Check-ins go ONLY through the `check_in_with_token` RPC; points are an append-only ledger (`score_entries`) priced by the admin-editable `score_actions` table.
- **Event page template** (`/events/[slug]`, agreed structure — reuse it for every event): sticky aside (category, title, excerpt = tagline, calendar/Strava links, date, Register) + article: top slideshow (`EventMediaSlideshow`: cover + gallery kept to the majority orientation via `getEventSlides()` in `src/lib/event-media.ts`, shown uncropped over a blurred backdrop; photos 3 s, clips play to their end; plain cover when there's only one item) → **Overview** (the at-a-glance icon box from the brief fields, then `events.overview`, 2–3 Markdown lines) → **Explore the details** (`events.body`) → Event brief cards (only if route notes / what to bring / coach tips are set) → route map → full-width **Gallery** (`events.gallery`, 0011) → newsletter. The body is plain Markdown; `remarkEventBody` (`src/lib/mdx-event.ts`) + `src/components/event-body.tsx` turn its patterns into designed blocks: a first `### Name · Place · Date` line → title + meta kicker; a list whose items all start with `**HH:MM**` → timeline (`**06:30** · Meet 1 · **Place:** …` adds a "Meet 1" label pill to that step — use it when there are several meet spots); the list under a "Pack your kit" / "Bring along" / "What to bring" heading → checklist (an item saying "mandatory"/"required"/"must" becomes a highlighted full-width "Mandatory" card); a closing `> …` line → coffee sign-off; `##` sections render as h3 with dividers. New events start from `BODY_TEMPLATE` in `admin-event-form.tsx`. Brief-field conventions: `start_time` = when the session starts moving (meet times live in the "Meet & move" timeline and the overview), `duration_minutes` = session length, `meeting_point` may list several places one per line (e.g. train meet + car meet), `finish_point` links to Maps too. The gallery (`src/components/event-gallery.tsx`) is shadcnblocks gallery4 adapted: Embla carousel aligned to the page column and bleeding right, one muted clip plays at a time (hovered / snapped card), tap opens a full-screen viewer with sound. Videos need a poster image (`poster`, an ImageKit path) because ImageKit can't make thumbnails on this account; the admin gallery editor (`admin-gallery-field.tsx`) captures one in the browser on upload, and cards fall back to the clip's first frame. Avoid spaces/parentheses in new media filenames.
- **Event lifecycle**: `events.is_past` is flipped by the pg_cron job `yrc-event-lifecycle` (every 15 min, Europe/Berlin day boundary) — past events move to `/events/past` and reject check-ins. QR check-in works only from 00:00 (Berlin) on the event day until 00:00 after the last day, enforced inside `check_in_with_token`/`get_event_for_checkin` (never rely on the cron for correctness). **Weekly runs** (0012): each week is its own events row (own registrations, QR token, check-ins), linked by `events.series_slug` (slug minus `-YYYYMMDD`, set by a trigger). The lifecycle job keeps every live series topped up to **6 upcoming weeks** (`WEEKLY_HORIZON`), copying the latest week forward; a series stops growing once its latest week isn't weekly. Admin/Agent edits to one week carry to the later weeks (`applyToFollowingWeeks`, `src/lib/event-series.ts`; form checkbox on by default, Agent `apply_to_following_weeks`). UI: `splitWeekly()` folds a series into its soonest date — `/events` has "Events" / "Weekly runs" tabs (`/events#weekly` opens the second; `WeeklySeriesCard` lists every open week), the home strip shows one row per series and the home highlight/grid are one-off only; cards carry `WeekTag` ("Nov · Week 4", week of the month) + `WeeklyBadge` ("Every Tuesday"); the event page shows `WeeklyRegister` (a dropdown of the open weeks, this page's date first and selected; Register acts on the chosen date; booked weeks are marked "✓ booked") and a past week links on to the next one; `/events/all` has a type filter.
- **Admins**: `admins` table (max 3, DB-trigger enforced), matched by linked `strava_athlete_id` OR by seat email == the member's auth email (so a magic-link login with the seat's email is instantly admin). Admin pages/actions use `requireAdmin()` from `src/lib/admin.ts`.
- **Members** (`/admin/members`, `/admin/members/[id]`): search, member detail (account, Strava link, points ledger, registrations, check-ins), edit name/location, leaderboard visibility, and a danger zone that deletes the auth user (cascades to profile, tokens, ledger, registrations, check-ins). Deletion is refused for your own account and for seat holders; actions live in `src/lib/actions/members-admin.ts`.
- **Admin Agent** (`/admin/agent`): chat that runs admin tasks through tools in `src/lib/agent/tools.ts` (events, registrations, members/points, score actions, admin seats, newsletter). Models go through the **Vercel AI Gateway** (AI SDK `ai`, key `VERCEL_AI_GATEWAY` or `AI_GATEWAY_API_KEY`; on Vercel the OIDC token also works); the admin picks Claude Haiku / Gemini Flash / DeepSeek in the chat header, from the server-side allowlist in `src/lib/agent/models.ts`. The provider-neutral loop is `src/lib/agent/loop.ts` (tools are declared without `execute`; read tools run immediately, any `mutates: true` call pauses for the admin to confirm); the server action is `src/lib/actions/agent.ts`. Add new capabilities as tools (validate inputs, revalidate affected paths). The composer's image button uploads to ImageKit and inserts the path.
- **Media uploads**: `MediaUploadField` / `useImageKitUpload` (`src/components/admin-media-upload.tsx`) upload straight from the browser to ImageKit with a one-time token signed by `getImageKitUploadAuth()` (`src/lib/actions/media.ts`, admin-only). Needs `IMAGEKIT_PUBLIC_KEY` + `IMAGEKIT_PRIVATE_KEY` (server-only). Event covers go to `/YRC/Events`.
- **Tests** (see `e2e/README.md`): `pnpm test` (Vitest, agent loop on a mock model) and `pnpm test:e2e` (Playwright, admin Agent + uploads in token-free test mode: scripted model, in-memory tools, intercepted ImageKit). Test mode (`YRC_E2E` + `YRC_E2E_SECRET`, `src/lib/e2e.ts`) is always off on production; never set it on a deployment.
- **Newsletter** (`/admin/newsletter`): Resend-backed — subscribers (`newsletter_subscribers` table + a Resend segment), broadcast drafts/scheduling/sending with stats, one-off/test emails, recent emails, suppressions, domain status. Ops in `src/lib/newsletter.ts`, actions in `src/lib/actions/newsletter-admin.ts`, shared plain-text → branded HTML renderer in `src/lib/newsletter-template.ts`. Needs `RESEND_API_KEY`.
- **Supabase clients**: `src/lib/supabase/{client,server,admin,public}.ts` — `admin.ts` is the service role (server-only, bypasses RLS); never import it from client components.
- **SEO**: `src/app/sitemap.ts` (static pages + every event/journal slug from the DB) and `src/app/robots.ts`. Canonical origin and "is this production" live in `src/lib/site.ts` — only Vercel production / yasrise.run is indexable; the Dokploy preview and local dev send `noindex` + `Disallow: /`. Default share card (OG image) in the root layout; event and journal pages use their cover.
