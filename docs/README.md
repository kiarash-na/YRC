# Docs — dev-work tracking (ICM style)

- `docs/backlog/` — ideas not started. One file per idea, `NN-slug.md` (NN = rough priority). Content: `# Title` + 1-3 bullets (what, why). Nothing else.
- `docs/active/` — work being built RIGHT NOW. One file per item: `# Title` + a tiny checklist of remaining steps.
- `docs/done/` — shipped work, rewritten as short technical notes for future coding agents: what was built, where it lives (files/tables), key decisions/gotchas. Max ~15 lines per file unless the source material is a reference report.
- Lifecycle: idea → backlog; started → move same file to active; shipped → move to done and rewrite as a tech note.
- One topic per file. Many small files, never one big file.
